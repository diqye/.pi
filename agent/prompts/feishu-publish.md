使用本机已安装的 `lark-cli`，把本地文档同步到飞书。

目标：$1
本地文件：$2
附加要求：${@:3}

请按下面流程执行，并直接完成，不要只给方案：

1. 先读取本地文件内容，确认文档标题、结构、是否包含本地图片引用。
2. 检查 `lark-cli` 是否可用，并确认登录状态可用；如果 token 过期，明确提示我先执行 `lark-cli auth login`，等待我确认后再继续。
3. 识别目标 URL 是飞书 `wiki` 还是 `docx`：
   - 如果是 wiki 链接，优先在该 wiki 节点下创建一个新文档；
   - 如果是 docx 链接，直接更新该文档；
   - 如无法直接判断，先用 `lark-cli` 探测最稳妥的写入方式。
4. 优先把 `$2` 作为 Markdown 内容同步到飞书：
   - 尽量保留标题层级、列表、代码块；
   - 若是新建文档，标题默认使用源文档主标题；
   - 若是更新已有文档，优先整体覆盖，避免残留旧内容。
5. 如果文档里有本地图片引用：
   - 识别相对路径图片；
   - 找到本地实际文件；
   - Markdown 导入后如果图片未成功带过去，则用 `lark-cli docs +media-insert` 逐张补插；
   - 插入位置尽量放在对应章节标题后、正文前；
   - 若无法精确定位，至少把图片插到最相关的小节附近，并说明处理结果。
6. 执行完成后，输出：
   - 最终飞书文档 URL
   - 是新建还是更新
   - 哪些图片已成功插入
   - 哪些内容可能仍需手动调整

执行要求：
- 优先直接操作，不要停留在解释层。
- 用 `read`/`bash` 检查文件和命令；需要时直接调用 `lark-cli`。
- 如果遇到 CLI 参数兼容问题，先查看对应 `--help` 再调整命令。
- 如果出现资源复制失败、图片丢失、token 失效等问题，明确说明原因并继续采用可行补救方案。
- 默认使用当前机器环境，不要泛化到其他平台。
